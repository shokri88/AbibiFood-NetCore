# مشکلات و محدودیت‌های شناخته‌شده بک‌اند

- محیط اجرای AI، SQL Server ندارد؛ اولین اجرای Migration توسط مالک روی SQL واقعی به خطای 1753 برخورد کرد. ناسازگاری طول FK کارکنان در کد اصلاح شد؛ مالک اجرای مجدد موفق Migration و بالا آمدن برنامه را گزارش کرد؛ آزمون کامل Cookie/JWT/هم‌زمانی روی SQL همچنان تأیید نشده است. مسیرهای HTTP احراز هویت با InMemory آزمایش شده‌اند.
- تست‌های EF InMemory، foreign key، unique constraint، rollback SQL و RowVersion SQL را اثبات نمی‌کنند.
- خطاهای فرم در بعضی actionها BadRequest نمایش می‌دهند و فرم با ورودی قبلی بازسازی نمی‌شود؛ بهبود UX لازم است.
- آپلود واقعی پنل با کنترل MIME/امضای فایل/اندازه اجرا شده؛ اسکن بدافزار، decode کامل، پاکسازی فایل بی‌مرجع و فضای ذخیره مشترک چندسروری هنوز انجام نشده‌اند. آزمون ذخیره انتها‌به‌انتها روی SQL و ارزیابی بصری مرورگر برای این تغییر باقی است.
- بعضی dropdownها شناسه غذا را نشان می‌دهند و نیازمند نام خواناترند.
- ساعات چندبازه/عبور از نیمه‌شب ذخیره می‌شوند؛ تشخیص بازبودن، هم‌پوشانی و استثنای تعطیلی روز خاص هنوز کامل نشده است.
- جزئیات قبل/بعد Audit و سیاست retention پاکسازی log هنوز تعریف نشده‌اند.
- قطع SQL، ثبت SQL ErrorLog را ناممکن می‌کند؛ fallback میزبان وجود دارد ولی replay پایدار هنوز نیست.
- Duplicate ناشی از race در unique index هنوز پیام conflict اختصاصی ندارد و ممکن است خطای ۵۰۰ عمومی شود.
- JWT کارکنان refresh یا فهرست ابطال تک‌توکن ندارد؛ انقضا ۳۰ دقیقه است. فعال‌بودن حساب و نقش‌های فعلی برای Bearer از Identity خوانده می‌شود. تغییر نقش Cookie تابع سازوکار stamp/اعتبارسنجی Identity است؛ لغو فوری همه نشست‌های Cookie اثبات نشده است.
- تنظیمات عمومی مدیریتی و انتقال کامل همه متن‌ها به Messages.fa.json هنوز انجام نشده است.
- افزودنی تودرتو، افزودنی اجباری و max در ردیف فروش هنوز سناریوی نهایی ندارند.
- فروش، OTP مشتری، درگاه، فاکتور و باشگاه واقعی خارج از دامنه این شروع هستند.

- CI اولیه بک‌اند به‌دلیل Billing حساب GitHub اصلاً Job را شروع نکرده است. اجرای دوباره تا رفع مانع راهکار نیست. تست SQL دستی نیز هنوز اجرا نشده؛ موفقیت CI را ادعا نکنید.

- ریشه خطای 1753: قاعده عمومی متن‌ها طول StaffBranches.UserId را ۵۰۰ می‌کرد، ولی Identity.Id طول ۴۵۰ دارد. اصلاح اولیه و تست schema اضافه شد؛ روش بازیابی بدون حذف دیتابیس در SETUP-DEPLOY آمده است.

- اصلاح بازخورد پس از 789c734 تست SQL واقعی و مرورگر ندارد؛ دانلود مرورگر آزمایشی ناقص بود. ۴۰ تست موفق شامل HTTP با InMemory جای آزمون بصری و رفتار FK/تراکنش SQL را نمی‌گیرد.
- حذف تصویر فقط رکورد را پاک می‌کند؛ فایل‌های قبلی برای جلوگیری از آسیب به ارجاع احتمالی دیگر حفظ می‌شوند. پاکسازی فایل بی‌مرجع هنوز نیازمند سیاست مستقل است.
- فارسی‌سازی ارقام عمومی و فیلد عدد/ساعت در مرورگر به JavaScript وابسته است؛ تاریخ‌ها از سرور شمسی هستند و ورودی ارقام فارسی در سرور پشتیبانی می‌شود. تقویم گرافیکی تاریخ هنوز اضافه نشده؛ ورودی شمسی متنی است.
