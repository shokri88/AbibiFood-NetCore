# وضعیت واقعی بک‌اند

## کد موجود
چهار پروژه Domain/Application/Infrastructure/Api؛ پنل Razor با صفحات مستقل داشبورد، شعب، مخزن، تصویر، گروه، عرضه شعبه، عضویت گروه، افزودنی، ساعات، ظرفیت، کارکنان و لاگ‌ها. API عمومی و writeهای مدیریت مشترک با CatalogService. Identity با سه نقش، Cookie پنل و JWT مدیریتی، rate limit ورود و کنترل شعبه سمت سرور.

AppDbContext با SQL Server و Migration اولیه شامل Identity و ۱۲ موجودیت دامنه. RowVersion ظرفیت/قیمت، کلیدهای یکتا و FKها تعریف شده‌اند. ErrorLogs و AuditLogs مستقل‌اند؛ لاگ تغییر کاتالوگ و تغییر اصلی در تراکنش مشترک ثبت می‌شود.

## اعتبارسنجی انجام‌شده
در شروع پروژه ۱۳ تست دامنه و سرویس موفق بود. در ادامه مورخ ۲۰۲۶-۱۰-۳۰، ۱۷ تست موفق و یک تست SQL به‌دلیل نبود محیط ردشده از اجرا (Skipped) است. چهار تست جدید، مسیر HTTP واقعی API و ورود Cookie/AntiForgery را با EF InMemory بررسی می‌کنند. Build بدون خطا و هشدار انجام شد. Migration تولید شده است. این تست‌ها صحت تراکنش، lock و RowVersion روی SQL Server واقعی را اثبات نمی‌کنند.

## هنوز انجام نشده
اعمال migration و ورود پنل روی SQL واقعی، ارسال پیامک/OTP مشتری، فروش، رزرو موقت، فاکتور، درگاه پرداخت، باشگاه واقعی و گزارش فروش. در داشبورد به‌جای آمار ساختگی، غیرفعال‌بودن ماژول فروش اعلام می‌شود. تعریف image path وجود دارد؛ upload فایل هنوز وجود ندارد.

اعتبارسنجی سمت مرورگر فرم‌های Razor با JustValidate محلی انجام می‌شود؛ مرجع نهایی اعتبارسنجی همچنان DataAnnotations و CatalogService سمت سرور است.

Smoke میزبان بدون SQL: /health/live=200، /Account/Login=200، /Admin/Index=302 و API مدیریت بدون Bearer=401. این آزمون فقط route/auth boundary را بررسی می‌کند، نه ورود موفق کاربر یا اتصال دیتابیس.

## ادامه کنترل دسترسی و پذیرش

اعتبار JWT در `Program.cs` با `OnTokenValidated` به فعال‌بودن حساب و نقش‌های فعلی Identity وابسته است. تست‌ها رد شعبه دیگر، محدودیت کارمند، حساب غیرفعال، حذف نقش مدیر و AntiForgery را پوشش می‌دهند. این نتیجه به معنای تست SQL یا مرورگر واقعی نیست.

تست `Integration/SqlServerAcceptanceTests.cs` برای migration، ظرفیت مشترک افزودنی/مستقل، RowVersion، unique index و rollback Audit نوشته شده اما اینجا اجرا نشده است. workflow دستی `sql-integration.yml` محیط SQL موقت می‌سازد؛ موفقیت اجرای آن هنوز تأیید نشده است.

اجرای اولیه CI بک‌اند در GitHub (run `41122471162`، مبنا `c36d134e`) پیش از شروع Job به‌دلیل Billing مسدود شده؛ این شکست، نتیجه Build کد نیست. رفع محدودیت حساب بر عهده مالک است.


## گزارش SQL واقعی مالک — ۲۰۲۶-۱۰-۳۱

مالک دیتابیس لوکال را با فایل‌های داده و لاگ در پوشه انتخابی خود ساخت. Restore ابزار EF نسخه 10.0.14 موفق گزارش شد. دستور database update، Build موفق داشت اما Migration `20261030194953_InitialCatalogAndIdentity` هنگام ساخت FK کارکنان با خطای 1753 شکست خورد؛ این گزارش، موفقیت Migration نیست. طول FK مدل و Migration اولیه از ۵۰۰ به ۴۵۰ هماهنگ شد؛ تأیید retry روی SQL مالک هنوز باقی است. جزئیات و بازیابی در SETUP-DEPLOY آمده است.

اعتبارسنجی اصلاح: Build با صفر خطا/هشدار، ۱۹ تست موفق و یک SQL Skipped. دو تست schema پیش از اصلاح fail و پس از اصلاح pass شدند.

## بهبود پنل و بارگذاری تصاویر — ۲۰۲۶-۱۰-۳۱

مبنای تغییر `8151b31` است؛ کامیت مالک `02c8037` و فایل تنظیمات او حفظ شدند. پنل Razor موجود با همان صفحات مستقل و Bootstrap RTL به‌روز شد: فیلدهای سه/چهارستونه در نمایشگر بزرگ و تمام‌عرض در موبایل، توضیحات تمام‌عرض، چک‌باکس‌های قاب‌دار، جدول جدا از فرم، رنگ‌های سرمه‌ای/سبزآبی و منوی دسته‌بندی‌شده. فونت وزیر حفظ شد؛ فرانت‌اند Hasti تغییر نکرد.

تصاویر از مسیر مخزن غذا ← ویرایش غذا ← تصاویر همان غذا مدیریت می‌شوند. ذخیره غذای جدید کاربر را به همان رکورد می‌برد. بارگذاری واقعی برای تصویر غذا و گروه افزوده شده است؛ جداول با `admin-ui.js` فیلتر متنی و مرتب‌سازی دارند. فیلتر فقط ردیف‌های بارگذاری‌شده را پوشش می‌دهد (برای لاگ‌ها ۱۰۰ مورد اخیر)، نه تمام دیتابیس. مهاجرت جدید لازم نیست.

اعتبارسنجی این مرحله: Build موفق بدون هشدار/خطا، ۲۴ تست موفق و یک تست SQL ردشده از اجرا (Skipped) به‌دلیل نبود SQL آزمایشی؛ بررسی syntax جاوااسکریپت و `git diff --check` موفق. HTTP تست، رندر صفحات پنل/فرم تصویر و رد فایل جعلی را پوشش داد؛ تست فایل، ذخیره واقعی PNG در پوشه موقت و پاکسازی، رد محتوای فعال/خالی و حجم اضافی را بررسی کرد. تست بصری مرورگر و ذخیره انتها‌به‌انتها روی SQL واقعی در محیط AI اجرا نشده‌اند. راهنمای استقرار فایل‌ها در CONFIGURATION و SETUP-DEPLOY آمده است.

## اصلاح بازخورد پنل — ۲۰۲۶-۱۰-۳۱ (پس از 789c734)

درخواست مالک: حذف رکوردها، تاریخ شمسی، ارقام فارسی، دسترسی مستقیم به تصاویر غذا، فوتر فرم، توضیح تک‌خطی تمام‌عرض، حذف فیلد مسیر تصویر گروه و breadcrumb با عنوان کوچک‌تر. همه روی معماری موجود اجرا شدند؛ فرانت‌اند مشتری، تنظیمات مالک، schema و قرارداد JSON API تغییر نکردند.

- کنار ویرایش هر غذا دکمه «تصاویر» وجود دارد. فرم بارگذاری و جدول تصاویر فقط در صفحه مستقل Images با foodId قرار دارند؛ دیگر برای رسیدن به تصاویر لازم نیست فرم غذا را ویرایش کنید.
- عملیات حذف POST و AntiForgery دارد؛ تأیید مرورگر، کنترل مجوز و وابستگی سمت سرور و Audit اضافه شدند. مدیر کاتالوگ/کارمند/دسترسی شعب را حذف می‌کند؛ کارمند فقط ظرفیت بدون مصرف شعبه خودش را. حذف مدیر، لاگ‌ها و ظرفیت دارای رزرو/فروش مجاز نیست؛ حذف آبشاری وجود ندارد.
- تاریخ‌های ظرفیت و گزارش‌ها شمسی‌اند؛ زمان گزارش به تهران نمایش داده می‌شود. تاریخ ظرفیت با قالب سال/ماه/روز شمسی وارد و با PersianCalendar اعتبارسنجی می‌شود. DateOnly و UTC ذخیره‌شده تغییر نکرده‌اند.
- اعداد نمایشی و ورودی عدد/ساعت فارسی می‌شوند؛ PersianFormValueProvider فقط فیلدهای عدد/ساعت فرم Admin را برای model binding نرمال می‌کند. رمز و متن آزاد تغییر نمی‌کنند. توضیحات تک‌خطی col-12، دکمه‌های فرم در نوار جدا با بوردر بالا، عنوان کوچک‌تر و breadcrumb پیاده شدند.
- گروه غذایی فقط Browse و پیش‌نمایش تصویر دارد؛ مسیر قبلی هنگام ویرایش بدون فایل از دیتابیس حفظ می‌شود.

اعتبارسنجی: Build بدون هشدار/خطا، ۴۰ تست موفق و یک تست SQL اجرا‌نشده؛ syntax دو فایل JS و diff check موفق. HTTP با InMemory ثبت ظرفیت با ارقام و تاریخ شمسی، حذف با CSRF/Audit، جلوگیری از حذف مدیر و redirect خارجی را بررسی کرد. تست‌های واحد تاریخ کبیسه/مرز روز تهران، وابستگی حذف و محدودیت شعبه را پوشش می‌دهند. تست SQL واقعی اجرا نشد. مرورگر Playwright موجود نبود و دانلود آن فایل ناقص داد؛ تست بصری/تعامل مرورگر تأیید نشده است.
